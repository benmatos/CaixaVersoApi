🚀 Inicialização da Aplicação

O que acontece quando você executa dotnet run — antes de qualquer requisição chegar

⚙️
Properties/launchSettings.json 1º
O ponto de partida. Define em qual porta o servidor vai escutar (ex.: https://localhost:7080), qual perfil usar (Kestrel ou IIS Express) e variáveis de ambiente como ASPNETCORE_ENVIRONMENT=Development.
Usado apenas pelo seu computador durante o desenvolvimento — não vai para produção.
📄
appsettings.json 2º
Carrega as configurações da aplicação: string de conexão com o banco, origens permitidas pelo CORS e nível de log. O arquivo appsettings.Development.json sobrescreve os valores quando o ambiente for Development.
🔌
Program.cs — registro de serviços 3º
O arquivo Program.cs registra tudo que a API vai precisar: Controllers, DbContext (conexão com o banco), Middlewares, Filters e CORS. É como montar a equipe antes de abrir o escritório.
✅
Servidor pronto para receber requisições 4º
O servidor começa a escutar na porta configurada. A partir daqui, qualquer pedido HTTP do cliente percorre o fluxo descrito no diagrama abaixo.

Do cliente ao banco de dados — e de volta

Cliente
O usuário clica num botão ou acessa um endereço no navegador. Isso dispara um pedido ao servidor — como ligar para um atendente e dizer: "Quero a lista de usuários".

Middlewares/
O pedido entra numa fila de checagem. O Middleware liga o cronômetro para medir quanto tempo a resposta vai demorar e passa o pedido adiante.

Converters/
O texto JSON que chegou do cliente é traduzido para objetos que o C# entende — como datas no formato correto. Pense num intérprete que converte o idioma do cliente para o idioma do servidor.
PIPELINE
4 🛡️
Filters/
StandardizedResponseFilter age como um porteiro: verifica a requisição antes de ela chegar ao Controller e já prepara o formato padrão da resposta.

5 🎮
Controllers/
O gerente da API. Recebe o pedido, identifica o que foi solicitado (GET /usuarios), verifica se os dados estão corretos e aciona a equipe responsável por buscar a informação.
ACTION

10 ✅
Cliente
O usuário recebe a resposta: os dados solicitados em formato JSON, junto com um código de status (200 = tudo certo) e o tempo que a operação levou.
RESPONSE
9 ⏱️
Middlewares/
O Middleware para o cronômetro e anota o tempo total no cabeçalho da resposta — como o garçom que registra quanto tempo o pedido demorou.
PIPELINE
8 📤
Converters/
O intérprete faz o caminho inverso: converte os objetos C# de volta para texto JSON antes de enviar ao cliente — garantindo que datas e números apareçam no formato esperado.
PIPELINE
7 📦
Filters/ + DTOs/
O porteiro embala a resposta num pacote padronizado — sempre com a mesma estrutura (sucesso/erro, dados, mensagem) — para que o cliente saiba exatamente o que esperar.
DEPOIS
6 ↩️
Controllers/
O gerente recebeu os dados do banco e prepara a resposta, escolhendo apenas as informações que o cliente pode ver (sem campos sensíveis como senhas).
RETORNO
💾
Repositories/ → Models/ → Data/ → SQL Server
📂 Repositories/ Decide como buscar os dados — encapsula todas as consultas ao banco em um só lugar.
🧩 Models/ Descreve o que é um usuário: quais campos existem e como eles se relacionam.
🗄️ Data/ (DbContext) Traduz os objetos C# para SQL e executa a consulta real no banco de dados.

Estrutura de Pastas — CaixaVersoApi

Pasta Função
Controllers/ Recebe as requisições HTTP e define os endpoints da API.
Ex.: UsuariosController.cs expõe as rotas de usuários.
Models/ Define as entidades do domínio (tabelas do banco).
Ex.: Usuario.cs representa o modelo de dados de um usuário.
DTOs/ Objetos de transferência de dados. Separa o que é exposto na API do modelo interno, evitando expor campos sensíveis.
Data/ Configuração do Entity Framework: contexto do EF, factory para migrations e a subpasta Migrations/ com os scripts de migração do banco.
Repositories/ Camada de acesso a dados. Isola as queries do restante da aplicação.
UsuarioRepository.cs · UsuarioSqlRepository.cs
Filters/ Filtros globais do pipeline do ASP.NET.
StandardizedResponseFilter.cs padroniza o formato de resposta da API.
Middlewares/ Componentes intermediários do pipeline HTTP.
ResponseTimeMiddleware.cs mede e registra o tempo de resposta.
Converters/ Conversores customizados de serialização JSON.
CustomDateTimeConverter.cs define como datas são serializadas/desserializadas.
Properties/ Configurações de inicialização do projeto (launchSettings.json): perfis de execução, portas e variáveis de ambiente.
